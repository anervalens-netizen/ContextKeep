Make the existing ContextKeep context useful at the point a coding agent resumes work. Reuse the memory programme, procedures and evaluation harness. Keep accepted knowledge, proposed reports, execution observations and verified effects distinct.

## Acceptance

### Retrieval

Fix expected identities and judgments before comparing results. Use the same consistent snapshot for both arms, separate development from independent cases, and preserve project/task/review/temporal scope. Do not relabel historical measurements as current quality. Report candidate recall, relevant top results, known incorrect/stale results and paired latency. Avoid unbounded scans. Keep saturation and omitted-result recovery truthful.

No regression is allowed in exact identifiers, authority, project/task isolation, source provenance, abstention, or existing no-replay behavior. A synthetic pass alone does not establish representative production quality.

### Continuity

A fresh session and task switch must resolve the relevant project/task, read its current state, preserve proposed/accepted labels and unresolved execution, and identify the correct next action. A compacted or uncertain context must be refreshed before effects. Repeated unrelated prompts must not trigger unnecessary full-memory reloads.

Distinguish instruction availability, actual tool calls, and correct agent behavior. Native client qualification does not establish universal activation in every host. Preserve existing user instructions and plugin identity. Do not edit plugin caches or bypass hook trust.

### Regression cases

Capture only significant failures. Cases must retain the failed request, evidence basis, expected behavior and scope. Draft cases are reviewed before entering a scored suite. Prefer deterministic assertions for identity, state and evidence invariants. Public examples are fictional and contain no production information.

## Source qualification and limits

The 24 frozen private retrieval controls retain identical ordered identities, scope, provenance, temporal metadata and completeness. Three independently authored positive controls and two negative controls are part of that set. These small controls show no general recall gain. The interleaved latency comparison remains within the declared bounded gate. Public synthetic tests reproduce the corrected Romanian intent mismatch and protect historical qualifiers, versions, authority and project isolation.

The continuity cohort contains four synthetic episodes and eight RO/EN formulations. One fresh agent, given only the rendered questions and evidence, passes all eight answer, action and source checks. This is fixed-evidence reasoning, not live retrieval or native Codex qualification. The original cohort remains unchanged. Eleven installer safety tests and the existing four-test workflow publication contract pass. Native no-model loading passes in an isolated profile; actual host behavior remains a distinct release check.

Private receipts retain the exact snapshot, manifest, raw answers, model invocation limits, measurements, publication identity and installed-state checks. Do not combine these bounded results into a general memory accuracy claim.

## Release and recovery

Use the existing reviewed release process. Preserve runtime identifiers and database schema unless a separate compatibility change is explicitly required. Keep production state and deployment receipts private. Apply source and plugin changes through their owning release workflows. Verify the deployed producer/client contract and meaningful behavior. Revert only this change if its bounded acceptance fails; never discard concurrent work.
